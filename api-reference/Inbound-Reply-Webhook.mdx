## Inbound Reply Webhook

The Inbound Reply webhook delivers the consumer's reply whenever someone texts back a message you sent through the [Texting endpoints](/api-reference/Texting-Overview). Unlike the [Communications webhook](/api-reference/Communications-Webhook), which reports that an interaction took place, this one carries the message text itself and identifies which of your sends it answers. You receive only your own organization's replies.

If no endpoint is configured, replies are still recorded and can be read with [List Text Messages](/api-reference/endpoint/Text-Messages).

## Webhook Notification

The webhook sends the reply body along with the id of the message being answered. Each delivery is signed, and the same reply may be delivered more than once, so use `messageId` to de-duplicate.

*Note: `inReplyTo` is null when the reply cannot be matched to one of your sends, such as a consumer texting in cold or a conversation idle more than 7 days. `debtorId` is "UNKNOWN" if the number has no send on record.*

**Headers:**
```
X-CollectWise-Event: text.inbound
X-CollectWise-Timestamp: 1755432000
X-CollectWise-Message-Id: 4d1a0b7c-9e2f-4c31-8a77-2b6f0d1e5c44
X-CollectWise-Signature: sha256=<hex hmac>
```

**Example Payload:**
```json
{
  "event": "text.inbound",
  "orgId": "05e617d3-2b96-45c4-be30-3ad2d9d3f842",
  "messageId": "4d1a0b7c-9e2f-4c31-8a77-2b6f0d1e5c44",
  "inReplyTo": "1b1f0a9e-6f4e-4f4b-9a2e-1f2d3c4b5a69",
  "accountId": "50041",
  "conversationId": "conv_087b83bb525d4fceaaa01a4234b6b012",
  "debtorId": "your-reference-number",
  "from": "+13313048434",
  "to": "55555",
  "message": "when is my payment due",
  "messageType": "sms",
  "mediaUrls": null,
  "receivedAt": "2026-08-17T12:00:00.000Z"
}
```

`messageId` is the id of the reply. `inReplyTo` is the `messageId` returned to you by [Send a Text](/api-reference/endpoint/Text-Send). `messageType` is `sms` or `mms`, and `mediaUrls` is only populated for MMS.

## Verifying the Signature

Each delivery is signed as `sha256=HMAC_SHA256(secret, "{timestamp}.{raw body}")`, using the secret as raw UTF-8 bytes and lower-case hex for the digest. Compute it over the raw request body before JSON parsing — re-serializing the parsed body changes the bytes and the signature will not match.

```javascript
const expected =
  "sha256=" +
  crypto
    .createHmac("sha256", secret)
    .update(`${headers["x-collectwise-timestamp"]}.${rawBody}`)
    .digest("hex");
```

To check your implementation, the secret `whsec` with timestamp `1755432000` and body `{"a":1}` produces:

```
sha256=0fe730fb2fb798f23d9b724ebb086d14d50ff27a15eb4bbb6f5cf70b334e4b59
```

*Note: without a configured signing secret we deliver unsigned and omit the signature header.*

## Responding

Respond `2xx`. A non-2xx response or a network error is retried up to 3 times with a short backoff, reusing the original timestamp and signature; a `4xx` is treated as permanent and not retried. To recover replies missed while your endpoint was down, use [List Text Messages](/api-reference/endpoint/Text-Messages) with the `since` parameter.

Send us your endpoint and signing secret to configure this webhook for your integration.
