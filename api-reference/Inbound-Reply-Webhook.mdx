## Inbound Reply Webhook

The Inbound Reply webhook delivers the consumer's reply whenever someone texts back a message you sent through the [Texting endpoints](/api-reference/Texting-Overview). It uses the same envelope as our other communication events, with the channel-specific details nested under `communication`, so an integration written against it will handle additional channels as they are added. You receive only your own organization's replies.

If no endpoint is configured, replies are still recorded and can be read with [List Text Messages](/api-reference/endpoint/Text-Messages).

## Webhook Notification

The webhook sends the reply text, the number it came from, and the id of the message being answered.

*Note: `inReplyTo` is null when the reply cannot be matched to one of your sends, such as a consumer texting in cold or a conversation idle more than 7 days. `debtorId` is "UNKNOWN" if the number has no send on record.*

## Example Payload

```json
{
  "event": "communication.inbound",
  "orgId": "05e617d3-2b96-45c4-be30-3ad2d9d3f842",
  "debtorId": "your-reference-number",
  "communication": {
    "type": "sms",
    "direction": "inbound",
    "messageId": "4d1a0b7c-9e2f-4c31-8a77-2b6f0d1e5c44",
    "inReplyTo": "1b1f0a9e-6f4e-4f4b-9a2e-1f2d3c4b5a69",
    "conversationId": "conv_087b83bb525d4fceaaa01a4234b6b012",
    "from": "+13313048434",
    "to": "55555",
    "message": "when is my payment due",
    "mediaUrls": null,
    "timestamp": "2026-08-17T12:00:00.000Z"
  }
}
```

`debtorId` is the reference you supplied when sending. Inside `communication`, `message` is the reply text and `from` is the consumer's number. `messageId` identifies this reply, and `inReplyTo` is the `messageId` that [Send a Text](/api-reference/endpoint/Text-Send) returned for the message being answered. `type` is `sms` or `mms`, and `mediaUrls` is only populated for MMS.

## Delivery

Respond `2xx`. A failed delivery is retried up to 3 times, so the same reply may arrive more than once. Use `communication.messageId` to de-duplicate. To recover replies missed while your endpoint was down, use [List Text Messages](/api-reference/endpoint/Text-Messages) with the `since` parameter.

Each request is signed with an `X-CollectWise-Signature` header so you can confirm it came from us. We provide the signing secret and verification details when we set up your endpoint.

Send us your endpoint to configure this webhook for your integration.
